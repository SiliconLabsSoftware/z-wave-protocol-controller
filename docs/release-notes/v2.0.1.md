# ZPC Version 2.0.1 - Release Notes (Oct 15, 2026)

ZPC is a Linux/macOS-based Z-Wave gateway application that functions as a central static controller in Z-Wave networks. It provides the host-side functionality of the Z-Wave Controller and interacts with the Z-Wave network through the Silicon Labs Network Co-Processor (NCP) controller. As a static controller, ZPC remains continuously powered and acts as the primary hub for managing and coordinating communication among all Z-Wave devices in a smart home network. ZPC provides network management, device control, and state synchronization capabilities through an MQTT-based communication interface.

This is the first certifiable general availability (GA) version of ZPC, with self-certified quality. It follows [v2.0.0](v2.0.0.md), keeps the same MQTT interface, adds several new features, and fixes inclusion, interview, and network-management problems found after v2.0.0.

- **GA:** first certifiable GA release, with self-certified quality.
- **New:** on-demand interview, Time CC v3, Firmware Update Meta Data Request/Prepare Get, Indicator Set/Report MQTT and Lifeline behavior, `network_status` on node properties.
- **API:** new `Network/Node/Interview` command; clearer factory-reset and remove-node MQTT behavior; DSK only when authenticated or provisioned.
- **Fixes:** inclusion/security, interview, network management, and command-class issues found in v2.0.0 (see [Bug Fixes](#bug-fixes)).
- **Platform:** unchanged from v2.0.0 (see [Chip Enablement](#chip-enablement)).

## Key Features

### New Features

- **On-demand interview.** Publish `zpc/<home_id>/Network/Node/Interview` with a `node_id` to run capability discovery again for a node that is already in the network. When the interview finishes, ZPC publishes `zpc/<home_id>/Interview/Report`.
- **Time Command Class, version 3.** ZPC answers date and time from the host operating system. The time source is Wi-Fi or the internet. Time Offset stays at zero, and Time Set or Date Set from the network is not applied.
- **Firmware Update Meta Data.** ZPC now supports Firmware Update Meta Data Request Get and Prepare Get.
- **Indicator.** An incoming Indicator Set is published on MQTT. After ZPC applies an Indicator Set, it sends an Indicator Report to the Lifeline destinations.
- **Node availability in node properties.** `Network/Node` properties reports include `network_status` (`online`, `offline`, or `unknown`), using the same values as `Network/Status/Report`.

### Enhancements

- A Version Report follows the specification. The No Operation command class is reported as version 0.
- Version capabilities are interviewed only when the node supports Version Command Class version 3.
- ZPC no longer advertises internal protocol command classes in the Node Information Frame.
- MQTT commands for a command the node does not support are dropped.
- Incomplete or out-of-range numeric values in MQTT payloads are rejected.
- Classic transmit power above 127 is sent as a 16-bit value. Older controllers that do not accept that value fall back to the previous encoding.
- The S2 timeout used during manual inclusion is longer, so a slow user response is less likely to fail the inclusion.
- A SmartStart node that fails inclusion no longer blocks the next inclusion. The DSK stays in the provisioning list so a later inclusion request can retry.
- ZPC sends a NOP only when self-destruction has just started, or when the NOP is addressed to a failed node.

No features or APIs were removed or deprecated in this release.

## API Changes

### New APIs

| New API | Notes |
|---------|-------|
| `zpc/<home_id>/Network/Node/Interview` | Request a (re-)interview for one node. Completion is reported on the existing `Interview/Report` topic. See the [Network Management MQTT API](https://github.com/SiliconLabsSoftware/z-wave-protocol-controller/blob/zpc-v2.0.1/components/network_manager/doc/network_management_mqtt_api.md). |

### Modified APIs

- Node properties reports include `network_status`. The other fields are unchanged.
- A rejected factory reset is published as a report instead of being silent.
- Retained MQTT topics for a removed node are cleared. Clients that kept reading those retained messages after removal will see them disappear.
- Add and Remove reports include a DSK only when that DSK was authenticated or came from the provisioning list. Non-secure, S0, and S2 Unauthenticated inclusions no longer publish a made-up DSK.

## Impact and Migration

v2.0.1 is compatible with a network created by v2.0.0. Existing MQTT clients keep working. No configuration migration is required.

Behavior changes that may affect clients (details under [API Changes](#api-changes) and [Bug Fixes](#bug-fixes)):

- Add and Remove reports no longer contain a DSK unless it was authenticated or provisioned. If an application treated that field as a real device DSK for non-secure, S0, or S2 Unauthenticated inclusions, stop using it unless the inclusion authenticated the DSK or the node was provisioned.
- Retained MQTT messages for a removed node are deleted. If an application depended on retained command-class state remaining after removal, subscribe to the removal report and drop local state there.
- `Network/Node/Add/Abort` can stop an inclusion that is waiting on the protocol.
- Transmit power values above 127 are no longer reduced before they are sent.
- If the serial (or IP) link to the NCP drops, ZPC logs that the Z-Wave API connection was lost and exits. Start ZPC again after the controller is back.
